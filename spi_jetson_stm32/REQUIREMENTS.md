# Jetson Orin Nano 与 STM32F4 SPI 通信项目需求说明

版本：v0.3；整理日期：2026-09-06。最新变更：按用户要求取消固定 36 字节响应，返回数据及逻辑帧长度由回调决定。

本文汇总本项目对话中提出的需求，作为后续开发和验收依据。“明确需求”指用户提出的约束；“当前实现约定”指为完成第一版而补充的设计，不能视为用户已指定的最终参数。本文不新增业务命令或变更当前代码。

## 1. 项目目标与交付顺序

基于已有本地 STM32 工程建立新项目，实现 Jetson Orin Nano 主机与 STM32F4 从机的 SPI 命令交互。开发顺序为：整理文档、实现通信层、实现协议层与命令回调、定义返回帧、代码检视和测试，最后将代码与文档一起提交到 [gzpic/stm32](https://github.com/gzpic/stm32)。

当前实现选择 STM32F407ZGTx，复用本地 HAL 跑马灯例程的启动、时钟及系统依赖，并参考 SPI 例程。必要依赖已收录到 `vendor/hal_example`，项目应能从仓库独立获取，不依赖开发者电脑上的原例程路径。

## 2. 明确需求

| 编号 | 需求 |
|---|---|
| R01 | Jetson Orin Nano 为 SPI 主机，STM32F4 为从机。 |
| R02 | 一次完整命令交互包含两次 SPI 操作：先写入命令，再读取返回。 |
| R03 | 写命令帧以 `0x30` 开始，以 `0x0A` 结束。 |
| R04 | 写帧头后依次包含 CMDID（1 字节）、帧总长度（2 字节）、SUBCMDID（1 字节），之后为命令数据。 |
| R05 | 读返回帧以 `0x60` 开始，以 `0x0A` 结束，不包含写帧中的 CMDID、总长度和 SUBCMDID 字段。 |
| R06 | 读写帧均在帧尾 `0x0A` 前放置 2 字节 CRC16。 |
| R07 | SPI 接收完成以 CS 上升沿为处理入口；在上升沿中断中把本次接收命令放入 buffer，随后结束中断。 |
| R08 | 后台轮询负责处理 buffer 中的命令，先检查整体帧格式、长度和校验和。 |
| R09 | 校验通过后，从命令组中找到 CMDID 和 SUBCMDID 均符合的命令回调并执行。 |
| R10 | 返回帧包含 1 字节命令执行状态，该状态由命令回调在执行结束时最后填写。 |
| R11 | 提交前检视代码，代码和需求文档一并推送到指定仓库。 |

SUBCMD 与 SUBCMDID 在现有文件中表示同一个字段。CS 与 NSS 表示同一根片选信号。

## 3. 当前帧定义

### 3.1 写命令帧

```text
0x30 | CMDID | LEN_LO LEN_HI | SUBCMDID | DATA[N] | CRC_LO CRC_HI | 0x0A
```

| 字段 | 字节数 | 当前含义 |
|---|---|---|
| HEAD | 1 | 固定 `0x30` |
| CMDID | 1 | 命令组标识 |
| LEN | 2 | 整帧长度，包含头、长度字段自身、数据、CRC 和尾；等于 N + 8 |
| SUBCMDID | 1 | 组内命令标识 |
| DATA | N | 命令参数，可为空 |
| CRC16 | 2 | 校验 HEAD 至 DATA 的所有字节 |
| TAIL | 1 | 固定 `0x0A` |

当前最大总长度为 256 字节，DATA 最多 248 字节。数据可以包含 `0x30`、`0xFF`、`0x0A` 等任意字节；接收方按事务实际长度和 LEN 判断边界，不能遇到 `0x0A` 就停止解析。

### 3.2 读返回帧

```text
0x60 | STATUS | RESULT[N] | CRC_LO CRC_HI | 0x0A
```

响应逻辑长度为 `N + 5` 字节：头 1 字节、状态 1 字节、结果 N 字节、CRC 2 字节、尾 1 字节。N 由回调填写，可以为 0～251；结果不补齐固定长度。CRC 覆盖头、最终状态和实际结果，不包含 CRC 自身及帧尾。

“最后填写状态”是回调的执行顺序，不代表状态必须位于帧尾。当前把 STATUS 放在 HEAD 后：回调先执行业务，填写 RESULT 和长度，最后填 STATUS；回调返回后，协议层才序列化返回帧并计算 CRC。状态和结果必须来自同一次同步回调。

| 状态值 | 含义 | 填写责任 |
|---|---|---|
| `0x00` | 成功 | 回调结束前填写 |
| `0x01` | 帧格式、长度、CRC 或接收错误 | 协议层，不进入业务回调 |
| `0x02` | 找不到匹配命令 | 分发层，不进入业务回调 |
| `0x03` | 参数错误 | 回调填写；内部调用参数错误也使用此值 |
| `0x04` | 执行失败或回调未填写状态 | 回调填写；分发前默认设为此值 |

返回帧不携带命令标识，当前通过唯一的未完成请求关联响应。主机应先检查返回帧及 CRC，再判断 STATUS；非成功状态下不使用 RESULT 作为有效业务数据。

## 4. 中断、缓冲区与后台分工

```text
Jetson 第一次 SPI：发送写命令帧
    ↓
STM32 DMA 接收 → CS 上升沿中断
    ↓
停止 DMA，记录长度/传输错误，复制数据到 command_buffer，发布 ready
    ↓ 退出中断
后台轮询：取出快照 → 格式/长度/CRC 校验
    ↓ 通过
查 CMDID 命令组 → 查 SUBCMDID 条目 → 执行回调
    ↓
回调先填结果、最后填状态 → 协议层组帧、计算 CRC → 装载发送 DMA
    ↓
Jetson 第二次 SPI：读取返回帧 → 从机恢复下一次接收
```

中断中不执行 CRC、查表或业务回调。后台处理期间保持快照有效，不允许 DMA 或后续中断覆盖它。当前使用单帧缓冲；占用期间的额外事务丢弃并计数，不实现流水线或多请求队列。等待 CS 拉高期间重复轮询不得重复执行同一回调。

所有长度边界和 CRC 检查必须在业务执行前完成。未知命令不得调用不匹配的回调。读事务也会触发 CS 上升沿，但占位数据不作为业务命令执行。

## 5. 命令扩展接口

命令注册采用两级表：`command_group` 保存 CMDID 和组内条目，`command_entry` 保存 SUBCMDID、回调和上下文。同一 `(CMDID, SUBCMDID)` 应唯一。

回调签名为 `void callback(const proto_request *request, command_response *response, void *context)`。回调只能访问本次请求，不得保留请求或响应指针供返回后使用；先填写 `response->data` 和实际 `response->size`，输出不得超过 251 字节；每条退出路径最后填写 `response->status`。同步回调返回后不能异步修改响应。

当前只提供 `CMDID=0x01、SUBCMDID=0x00` 回显示例，按请求 DATA 的实际长度返回。具体控制、采集等业务命令尚未定义，不属于已完成的业务范围。

## 6. 暂定参数与待确认事项

以下为当前代码采用的补充设计，而非最初需求中的指定值；后续变更必须同步修改主从两端、文档及测试。

| 项目 | 当前实现约定 |
|---|---|
| CRC 算法 | CRC16/MODBUS，init=`0xFFFF`，反射多项式 `0xA001`，xorout=0；仅借用校验算法，不采用 Modbus 报文协议 |
| 多字节字段 | 长度、CRC 均低字节在前 |
| SPI | Mode 0、8 bit、MSB first、100 kHz、CS 低有效 |
| 两次操作 | 两个独立片选窗口；读操作 MOSI 发送 256 个 `0xFF` 产生最大帧时钟，MISO 返回变长逻辑帧，剩余为 `0xFF` 填充 |
| 时序 | 主机启动等待 100 ms；事务之间 CS 高电平至少 10 ms |
| 响应容量 | STATUS 1 字节 + RESULT 0～251 字节，逻辑帧为 5～256 字节 |
| 硬件资源 | F407 SPI1，PA4/PA5/PA6/PA7；DMA2 Stream0/3 Channel3；EXTI4 |
| 缓冲 | 单帧邮箱；DMA 缓冲 257 字节，其中 1 字节用于检测超长，不放在 CCM |

待根据实际设备确定：STM32 具体型号和晶振、Jetson 载板引脚与 pinmux/设备节点、最终 CRC 和字节序、业务命令及返回数据含义、是否需要变长响应或 READY 握手。

当前没有 READY 引脚，10 ms 间隔依赖后台和回调及时完成，并非任意负载下的完成保证。长耗时命令加入前应调整完成通知方案。读失败不自动重发写命令，以免重复执行业务；从机允许新的写命令替换未读响应，以便重新同步。
