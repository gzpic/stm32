# Jetson 与 STM32 I2C 配置及测试记录

记录日期：2026-09-12。

## 结论

Jetson Orin Nano 作为 I2C 主机、STM32F407ZG 作为地址 `0x42` 的 I2C1 从机，基础双向通信已经通过：Jetson 能读取 STM32 预置寄存器，也能写入一个字节后正确回读。该结果证明当前管脚、上拉、地址匹配和基础收发中断可用。

当前测试是独立的最小寄存器式从机，不包含正式命令帧、超时、长数据、业务并发和掉线恢复。因此结论是“基础 I2C 链路可用”，不是“正式业务协议全部完成”。

## 最终接线

| Jetson Orin Nano J12 | 信号方向 | STM32F407ZG | 说明 |
|---|---|---|---|
| Pin 5 | Jetson -> STM32 时钟 | PB6 / I2C1_SCL / AF4 | I2C 时钟 |
| Pin 3 | 双向 | PB7 / I2C1_SDA / AF4 | I2C 数据 |
| Pin 6 | - | GND | 两板必须共地 |

两端均使用 3.3 V 逻辑。Jetson 载板的这组 I2C 线上已有约 2.2 kΩ 到 3.3 V 的上拉，因此 STM32 PB6/PB7 配置为开漏复用且不启用内部上下拉。不得把任一 I2C 信号配置成推挽输出。

## 管脚选择依据

STM32F407ZG 的 I2C1 可用两组 AF4 管脚：

| 组合 | SCL | SDA | 本次结果 |
|---|---|---|---|
| I2C1 重映射组 | PB8 | PB9 | 接入后两线约 0.7～0.9 V；即使临时关闭 I2C1 并把 PB8/PB9 改为输入，现象仍存在，因此本轮不使用 |
| I2C1 默认候选组 | PB6 | PB7 | 接线后总线恢复空闲，最终读写测试通过，确定采用 |

`PC6` 不在 STM32F407ZG 的硬件 I2C 管脚复用表中，不能用于当前 I2C1 外设。PC6 只有在自行实现软件模拟 I2C 时才能作为普通 GPIO 使用，本测试没有采用软件模拟方式。

I2C 与 I2S 也不是同一种外设。I2C 使用 SCL/SDA 开漏总线；I2S 用于音频，通常使用 CK、WS、SD 和可选 MCK，不能因为名称接近而互换管脚。

## Jetson 配置

本机 J12 Pin 3/5 对应 `/dev/i2c-7`，控制器为 `c250000.i2c`。Jetson 是总线主机，负责产生 SCL；测试时使用系统的 `i2c-tools`。

断开 STM32 时，Pin 3 和 Pin 5 对地均测得约 3.3 V。改接 PB6/PB7 后，总线扫描能正常结束，没有出现 SCL/SDA 持续低电平导致的总线卡死。

`i2cdetect -y 7` 在本机不会显示 `0x42`，原因是该控制器不支持 `i2cdetect` 对此地址默认使用的 SMBus Quick Write，工具会跳过对应地址。这不能用来判定从机不存在。本项目使用明确的读命令验证地址。

## STM32 最小从机配置

测试源码和 Keil 工程：

```text
stm32/i2c_basic_test.c
stm32/i2c_basic_test.uvprojx
```

关键配置如下：

| 项目 | 配置 |
|---|---|
| MCU | STM32F407ZGTx，8 MHz HSE，168 MHz 系统时钟 |
| 外设 | I2C1 从机 |
| 本机地址 | 7 bit 地址 `0x42` |
| GPIO | PB6/PB7，AF4，开漏，无内部上下拉 |
| APB1 外设时钟 | 42 MHz |
| 中断 | `I2C1_EV_IRQn`、`I2C1_ER_IRQn` |
| 数据模型 | 16 字节寄存器数组，先写寄存器地址，再读写数据 |

源码直接配置 I2C1 寄存器。DAP 实测关键值为：

```text
GPIOB_MODER = 0x0000A280
GPIOB_OTYPER = 0x000000C0
GPIOB_AFRL = 0x44000000
I2C1_CR1 = 0x0401
I2C1_CR2 = 0x072A
I2C1_OAR1 = 0x4084
```

其中 `OAR1=0x4084` 对应 7 bit 从机地址 `0x42`。主机提供实际 SCL，所以从机模式下不能把 `CCR` 值当作总线实际频率；实际波形频率应由 Jetson 控制器和测量结果确定。

## 实测步骤与结果

读取预置寄存器 0：

```sh
i2cget -y 7 0x42 0x00 b
```

实测输出：

```text
0xa5
```

向寄存器 2 写入 `0x5A` 并回读：

```sh
i2cset -y 7 0x42 0x02 0x5a b
i2cget -y 7 0x42 0x02 b
```

实测回读：

```text
0x5a
```

DAP 同时读到地址匹配、接收、发送和 STOP 计数增长，寄存器数组的第 2 项变为 `0x5A`，证明数据确实进入 STM32，而不是 Jetson 本地回环或命令输出假象。读取结束时主机通过 NACK 结束最后一个字节会触发 STM32 的 AF 标志，这是 I2C 从机发送结束的常见现象，本测试中不代表数据错误。

## 扩展链路验证

同日使用本文件所列的 STM32 最小从机固件和 Jetson `/dev/i2c-7` 完成如下追加测试。测试前用 Keil 命令行构建 `stm32/i2c_basic_test.uvprojx`，随后通过 CMSIS-DAP 下载 `stm32/OutputI2C/i2c_basic_test.axf` 并复位。

| 项目 | 方法 | 结果 |
|---|---|---|
| 连续读写 | 写入 16 字节 `10 21 ... FE 0F` 后，以重复起始读回 16 字节 | 通过 |
| 环形边界 | 从寄存器 `0x0E` 连续写 `AA BB CC DD` 后读回 | 通过 |
| 非法地址 | 对 `0x43` 发起读 | 主机得到 `Remote I/O error`，符合从机未 ACK 的预期 |
| 最大传输量 | 单次写入“寄存器指针 + 256 字节”，随后一次读取 256 字节 | 通过；读回的 16 字节环形窗口为 `F0` 至 `FF` 并正确重复 |
| 随机压力 | 覆盖长度 1--16、起始寄存器 0--15 的 256 组扫测，加 2000 组固定种子随机读写 | 2256 组全部通过，耗时 6.613 s |
| 复位恢复 | CMSIS-DAP 连续复位 STM32 5 次，每次立即由 Jetson 以重复起始读取寄存器 0、1 | 5/5 返回 `A5 01` |

此前的 1000 轮固定 4 字节写后读压力测试也全部通过，共计 2000 次 I2C 事务，耗时 4.077 s。

## 后续验收

当前结果证明 PB6/PB7、`/dev/i2c-7`、地址 `0x42`、从机地址匹配、中断收发、重复起始、256 字节量级传输和 MCU 复位后恢复均可用。它不等同于正式业务协议通过：还需实现并测试正式命令帧、BUSY 状态和只读重试、帧 CRC、超时与总线恢复、STM32 忙碌期间行为、掉电/拔线恢复及业务并发。最小测试的 16 字节寄存器模型不能直接作为最终协议。

## 正式帧接收比对

正式 I2C 从机固件下载后，可在工作站项目根目录运行：

```powershell
D:\conda\python.exe tools\i2c_frame_test.py
```

该工具由 Jetson 以 `i2ctransfer` 直接发送原始命令帧，再通过 CMSIS-DAP 读取 STM32 `command_rx` 缓冲区并逐字节比较。随后工具读取固定 256 字节响应窗口，逐字节比较“响应帧加 `FF` 填充”。当前覆盖空载荷（写 8、读 5 字节逻辑帧）、含 `30 FF 0A 00` 的特殊字节载荷（写 13、读 10 字节逻辑帧）和 248 字节载荷（写 256、读 253 字节逻辑帧）。实测三项均通过，证明写帧和读帧的帧头、字段、CRC16、帧尾及读填充均正确。

## 板载传感器命令验证

正式 I2C 固件加入传感器后，由 Jetson 以 `build/i2c_request /dev/i2c-7 0xF0 SUBCMD` 调用。每个命令均先写标准命令帧，再读取固定 256 字节响应窗口。

| 命令 | 实测返回 | 解析 | 结果 |
|---|---|---|---|
| `F0 02` | `status=0 data[2]: 9D 0B` | 小端 `0x0B9D=2973`，即 `29.73°C` | 通过 |
| `F0 03` | `status=0 data[1]: 12` | 相对光照强度 `18/100` | 通过 |
| 连续读取 | 温度五次为约 `31.98~32.30°C`，光照五次均为 `18` | 读帧、业务处理及后续新命令均正常 | 通过 |

`F0 02` 采集 STM32F407 内部温度传感器，是 MCU 的结温近似值。换算使用原“实验20 内部温度传感器实验”的典型 `V25=0.76 V`、斜率 `2.5 mV/°C` 参数；其绝对值未经单板校准，适合温升趋势监测，不应替代经校准的环境温度传感器。`F0 03` 采集 LS1（PF7/ADC3 通道 5），数值为原“实验21 光敏传感器实验”的 `0~100` 相对亮度映射，并非 lux。
